# 插件和隔离实施设计

用户已明确批准实施调研建议：先备份，接入Context7、Quota、Plannotator，云端low实测，所有新需求在独立worktree实施和验证，原工程代码不改，验证后脱敏发布。记忆/DCP不加入。

采用固定版本插件、Plannotator user-managed与现有角色权限集成。以小型独立worktree策略插件封装原生worktree创建和会话移动，已处于linked worktree时复用；本地实施/测试角色在非linked目录被阻断。新增工程worktree登记继承来源工程的原生/通用模式，不借此换策略。原目录、未提交内容不stash/reset/自动合并。git元数据的必要更新不视为修改原代码。

计划仍由云端编写和审查，Plannotator承载真实用户批注和批准，批准后保持云端协调并委派固定local-worker。文档工具仅按需调用且不上传私密源码。Quota观察真实额度，未知明确未知，不静默切换模型。模型选择仍由当前主会话决定，low只用于测试而不强制日常默认。

备选直接套默认插件工作流会重写现有规划，故使用user-managed；仅提示worktree不足以发现误派发，故加运行时目录校验。不是OS沙箱，不能阻止同用户进程绕过；验收对比原工程内容与未提交状态。没有Git或不能创建隔离环境时停止实施，不退回原目录。
