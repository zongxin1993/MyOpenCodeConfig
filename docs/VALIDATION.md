# 验证范围

基线环境：OpenCode Desktop 2.3.0，macOS，Python 3.9.6。工作流使用云端 OAuth 模型和一台本地 OpenAI 兼容服务；此仓库没有记录该机器地址、凭据或个人文件路径。

## 已验证

- 生成器9项测试：权限迁移、默认与逐角色模型、身份提示同步、自定义档位冲突和更新、幂等、无效输入不写入、备份及文件权限、保留无关配置。
- 在独立目录解压后运行同一测试，不依赖原工程路径或额外 Python 包。
- 当前配置和示例符合基线 OpenCode V2 Schema；原权限、Provider默认参数、模型能力和限制、其他设置在实际应用时保留。
- 实际原生子代理调用：cloud-workflow → local-worker 测试 → cloud-review 只读审计 → 同一 local-worker 归档，全部完成。实际模型记录与角色分工相符。
- 此前完整任务实测过 GrillMe 澄清、Superpowers 计划及“预设缺陷 → 云端 BLOCKED → 本地修复复验 → 云端复审 PASS”的闭环。预设缺陷是测试注入，确认是一次性测试的模拟回答，不冒充真实工程用户批准。
- Desktop 主对话实际显示阶段、协调模型、执行模型及派发／返回状态；长卡片标题可能截断，正文的模型字段可完整显示。
- 按后续偏好移除本地工作流思考档位，运行时已确认本地无命名 variant，现有 Provider／服务参数与云端档位保持。

仓库提供的是脱敏模板，实际部署测试的私密配置、会话、完整输出日志和备份没有随仓库发布。

## 从零配置的验证边界

发布前在临时目标验证基础配置＋模型映射能够生成、应用、备份且重复生成无差异；检查技能锁定版本路径与完整资源可用。技能上游版本固定在 skills.lock.json，基础 Superpowers 与 GrillMe 的关键入口与现有部署一致；审计技能为可取得的官方固定版本，未宣称与本机可能经过适配的副本逐字相同。

未在一台全新机器上重新登录 OAuth、部署推理服务，再对所有版本与平台完整认证。尤其不宣称 Windows、任意模型、任意工具调用、插件组合或项目权限均可用。新机器按 README 的小任务先验收。

生成器测试不等于真实模型任务测试；目录存在不等于技能可加载；角色配置正确也不等于模型必定遵守流程。

## 本地运行检查

```sh
python3 -m unittest discover -s tests -v
python3 configure.py --models models.local.json
```

应用后在 OpenCode 中核对角色、模型和技能，再执行 README 的小任务。工作流修改后，至少验证单次实施与独立审计；修复回路有变化时再加入有明确说明的缺陷注入测试。
