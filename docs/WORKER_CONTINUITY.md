# 执行会话续接与恢复

云端主协调者负责把审计问题交回本地执行者。独立审计员负责读取源码、核验测试证据并返回结论，不负责寻找或派发 local-worker；审计子会话缺少 worker 标识不影响它返回审计报告。

启用 `routing.cloud_model: "session"` 时，cloud-session-router 在真实 `subagent` 完成回执中读取 `metadata.sessionID`，保存到宿主提供的插件私有持久存储。键按主会话、项目和实际工作目录隔离，不在业务仓库创建文件，不保存提示正文、源码或凭据。记录包含执行会话、角色、模型及派发调用标识；这只是路由记录，不是测试、审计通过或 Freeze 完成证据。

每次云端请求都会收到 `PERSISTED WORKER CONTINUITY`：插件直接核对宿主子会话的父会话、项目、目录、角色及本地模型。模型即使忘记 `sessionID`，后续不带标识的本地修复委派也会自动补上原 worker。云端模型及档位仍跟随主会话选择，本地模型仍沿用配置，没有新增本地推理参数。

旧任务没有登记时，插件完整分页读取当前主会话、目录下的子会话；仅有一个合格本地执行者时自动恢复登记。不会按标题、最近时间或模型生成的文本猜测标识。插件重载、正常上下文压缩不会清除已保存记录。

| 状态 | 行为 |
|---|---|
| WORKER_READY | 修复、复验和收尾复用原 worker |
| NO_WORKER_YET | 可以按已批准计划首次派发；派发前先保存待确认状态 |
| WORKER_DISPATCH_UNCERTAIN | 原派发可能已产生执行者；先核对宿主记录，禁止重复创建 |
| WORKER_AMBIGUOUS | 多个候选，保留阻塞并核对原派发凭证 |
| WORKER_UNAVAILABLE / WORKER_IDENTITY | 原会话不可读、归属或模型发生变化；禁止静默换人 |
| WORKER_HISTORY_INCOMPLETE / WORKER_REGISTRY_INVALID | 查询或记录不可信；保留阻塞，不以新建执行者绕过 |

登记无法恢复时，明确保留审计报告和当前执行证据，不再“等待原执行者自行回报”。若计划强制同一执行会话，替换须先获明确例外授权、确认旧执行者没有运行，再交接完整计划、当前差异、未解决问题与原始测试证据。插件不会自动取消旧任务或自动换人，也不会解除 Freeze。

当前范围：持久化/恢复由本地 OpenCode V2 的插件 storage、session 和 tool hooks 提供。它不是跨机器迁移服务，不承诺多个独立宿主进程共享同一任务的分布式锁；同一宿主内首次派发串行防重。切换固定云端路由模式后不加载此插件，需先单独适配再声称具有同样的恢复保障。新配置需要宿主重新加载；已经发出的请求沿用其旧上下文。
